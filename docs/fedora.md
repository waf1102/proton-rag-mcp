# Fedora migration checklist

Migration is documented, not deployed. Use the reviewed commit and pinned images on the target host; do not copy the Debian container storage tree wholesale.

- Verify target CPU/RAM/disk and supported rootless Podman/Quadlet versions. Install Python, uv and the required rootless networking tools. Create the intended non-root service account and validate subordinate UID/GID ranges and user systemd availability.
- Obtain owner approval for encrypted storage/unlock design. Verify actual LUKS mappings and swap protection. Place all persistent RAG and Bridge data on the intended encrypted filesystem. Do not claim encryption from a directory name or copied architecture document.
- Keep Bridge setup, account authentication and keyring provisioning operator-controlled. Verify headless keyring access in the actual user service context; do not copy plaintext credentials into Git or logs. Inspect Bridge's local port mapping and validate its certificate for the configured host. Preserve the existing account and mailbox flags.
- Install the pinned application Quadlets and user daemon unit, using the target account home and the same stable app layout. Keep external port mappings on `127.0.0.1`. Verify `rag-network` resolution; host loopback and container loopback remain distinct.
- Keep SELinux enforcing. Named Podman volumes should receive appropriate labels automatically; if replacing them with bind mounts use a deliberate private `:Z` or shared `:z` label as appropriate. Do not relabel the whole home or disable SELinux to clear errors. Inspect AVC denials and narrowly correct paths/labels.
- Transfer approved application state only with a consistent backup while the three RAG services are stopped. Preserve the budget ledger across migration to avoid resetting the cap; never run source and destination with independent writable ledgers for the same key. Preserve UIDVALIDITY/UID mappings, source JSON, vectors and caches together. Verify ownership and mode-0600 secrets through secure injection.
- Start with synthetic fixtures. Run the full tests, actual local API lifecycle check, both SDK clients, and service restart checks. Verify model digest, resource limits, rootless ownership, loopback listeners, healthy services and persistent data after restart.
- User linger and host boot/unlock changes require owner approval. Test real reboot only when separately authorized. Record whether services wait for decrypted storage and Bridge readiness instead of assuming a boot-time target.
- Enable private ingestion or cloud exposure only after the privacy/storage decisions. Revalidate no-mailbox-write tests. Any future copy tool must prove source UID/UIDVALIDITY, flags and counts unchanged, and refuse unsafe server behavior.
